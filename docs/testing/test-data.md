# Test data

Two sources of test data, both **entirely synthetic**: no third-party, licensed or private datasets are used.

1. **Sample files** in [`samples/`](../../samples/) for manual and demo use, generated by
   [`backend/scripts/generate_samples.py`](../../backend/scripts/generate_samples.py).
2. **Programmatic builders** in [`backend/tests/builders.py`](../../backend/tests/builders.py), used by the
   automated tests to create inputs next to the assertions that use them.

## Sample files

Geometries are simple shapes placed around two fictional sites: an open-cast mine near Raipur, Chhattisgarh
(81.62°E, 21.31°N) and a parcel block near New Delhi (77.209°E, 28.614°N). Names and attribute values are
invented; attribute values (for example `declared_area_ha`) are not meant to match the measured results.

```bash
cd backend
python scripts/generate_samples.py     # requires the dev extras (GeoPandas); rewrites ../samples/kml and ../samples/shapefile
```

KML output is deterministic. ZIP files differ byte-wise between runs because entries carry file modification
times, so a regenerated ZIP has a new SHA-256 and is treated as a new upload (no dedup hit).

### Expected outcomes

The outcomes below were obtained on 2026-10-08 by running the ingestion and geoprocessing code
(`inspect_shapefile_zip`, `extract_shapefile`, `scan_kml`, `process_dataset`) over each file with default settings
(`MEASUREMENT_STRATEGY=local_equal_area`), without the HTTP API or database. The API returns the same values
rounded to 0.01 m / 0.01 m². For `mine_site_survey.kml` the totals and counts also match an end-to-end run through
the UI, API, worker and Supabase ([screenshot](../assets/title-block-dark.jpg)).

|---|---|---|---|---|
| `kml/mine_site_survey.kml` | KML, WGS 84 (EPSG:4326 per the KML spec) | 13 in 4 layers | `COMPLETED_WITH_ERRORS` | Folders as layers, holes, repair, multi-geometries, Z values, mixed collection, missing geometry |
| `kml/parcel_block_wgs84.kml` | KML, WGS 84 | 12 polygons | `COMPLETED` | Clean happy path; area varies with latitude |

| `shapefile/plots_web_mercator.zip` | Shapefile, EPSG:3857 (`.prj`) | 6 polygons | `COMPLETED` | Web Mercator input is never measured in Mercator |
| `shapefile/plots_no_prj.zip` | Shapefile, UTM 43N coordinates, **no `.prj`** | 6 polygons | `COMPLETED_WITH_ERRORS` | CRS never guessed; `crs` override |

Every Shapefile ZIP contains `.shp`, `.shx`, `.dbf` and `.cpg`, plus `.prj` except in `plots_no_prj.zip`. No sample
produces `ZIP_ENTRIES_IGNORED`, `HIGH_PROJECTION_DISTORTION` or `CRS_OVERRIDDEN` with default upload options.

#### `kml/mine_site_survey.kml`

Four `<Folder>` elements become four GDAL layers (driver `LIBKML` in the development environment): *Lease and pits*
(4), *Stockpiles* (1), *Haul roads* (3), *Survey control* (5). Counts: 8 `MEASURED`, 3 `NOT_APPLICABLE`,
1 `UNSUPPORTED`, 1 `FAILED`. File warnings: `Z_COORDINATES_IGNORED`, `UNSUPPORTED_FEATURES`. Totals: 16,312,197.96 m²
of polygons, 6,094.78 m of lines. Every feature is measured in LAEA centred at 21.5°N, 81.5°E.

|---|---|---|

#### `kml/parcel_block_wgs84.kml`

12 placemarks (no folders, so one layer named after the document, *Synthetic parcel block*), each 0.001° x 0.0008°.
All `MEASURED`: 8,671.15 m² (row 1), 8,671.07 m² (row 2), 8,670.99 m² (row 3); the same angular size covers less
ground further north. Total 104,052.89 m². No warnings.

#### `shapefile/plots_utm43n.zip`

Six 0.0012° x 0.001° plots generated in WGS 84 and written in UTM 43N. CRS reported as `EPSG:32643`, *WGS 84 / UTM
zone 43N*, source `FILE`. Each plot is 13,006.72 m² (total 78,040.32 m²). With `MEASUREMENT_STRATEGY=utm` the same
plots measure 13,011.30-13,011.40 m² in `EPSG:32643`, +0.035 % against the geodesic reference: below the 0.1 %
threshold, so no `HIGH_PROJECTION_DISTORTION`. Attributes: `plot_no`, `owner`, `landuse` (no name-like field, so
`name` is null).

#### `shapefile/plots_web_mercator.zip`

The same six plots written in EPSG:3857. CRS `EPSG:3857`, *WGS 84 / Pseudo-Mercator*. Each plot measures
13,006.72 m², identical to the UTM file: the source CRS only determines how coordinates reach WGS 84. Computing area
directly in the file's Mercator coordinates would give 16,939.4 m² per plot (+30.2 % at 28.6°N).

#### `shapefile/plots_no_prj.zip`

The UTM 43N plots with the `.prj` removed. Expected: `COMPLETED_WITH_ERRORS`, `crs: null`, file warning
`CRS_MISSING`, all 6 features `FAILED` with `CRS_MISSING`. Coordinates are kept in `geom_raw` and returned as
`raw_geometry` (GeoJSON `geometry` is null), the file summary has no `bbox`, and the map shows "No feature could be
placed on the map."

Uploaded again with `crs=EPSG:32643`: `COMPLETED`, `crs_source: USER_OVERRIDE`, every plot 13,006.72 m², no warnings
(nothing was declared, so nothing was overridden). The override changes the job fingerprint, so this is a new job.

A wrong override is not detectable when the coordinates still land inside lon/lat bounds: `plots_web_mercator.zip`
uploaded with `crs=EPSG:32643` completes with a `CRS_OVERRIDDEN` warning but places the plots near 15.5°N, 137.5°E
with ~4,565 m² each.

#### `shapefile/roads_wgs84.zip`

Three LineStrings near the mine site; all components are inside an `export/` folder in the archive (components
are matched case-insensitively in the same folder as the `.shp`, and extraction flattens the paths). Layer `roads`. Lengths: Access road 4,701.94 m, Ramp 1 691.88 m, Ramp 2 606.93 m
(total 6,000.75 m). Names come from the `name` attribute.

#### `shapefile/borewells_points.zip`

Four points with `well_id` and `depth_m`. All `NOT_APPLICABLE`; `total_area_m2` and `total_length_m` are null (not 0).

## Programmatic builders (`backend/tests/builders.py`)

Tests generate their own inputs instead of reading opaque binaries, so each fixture's intent sits next to its
assertion and variants are one argument away.

| Builder | Produces |
|---|---|
| `kml_point`, `kml_line`, `kml_polygon(shell, holes)` | KML geometry fragments |
| `kml_placemark(name, geometry_xml, data)` | Placemark with optional `ExtendedData`; no geometry when `geometry_xml` is empty |
| `kml_document(*placemarks, folders=..., prolog=...)` | Complete KML bytes; `folders` creates multi-layer documents, `prolog` injects text before `<kml>` (used for DTD/entity attacks) |
| `square(lon, lat, size_deg)`, `BOWTIE` | Ring coordinates; `BOWTIE` is a self-intersecting ring near 77°E, 28°N |
| `shapefile_zip(geometries, crs=..., attributes=..., stem=..., folder=..., drop=..., extra_entries=..., workdir=...)` | A real Shapefile written by GDAL (GeoPandas + pyogrio) and zipped; `crs=None` writes no `.prj`, `drop={".prj"}` removes a component, `folder` nests entries, `extra_entries` adds arbitrary members |
| `zip_bytes(entries, compression=...)` | Arbitrary archives (traversal names, bombs, missing components) |
| `zip_with_symlink(target)` | Entry whose Unix mode marks it as a symbolic link |
| `zip_with_encrypted_flag()` | Archive with the "encrypted" general-purpose flag set in local and central headers |

The performance tests build their own dataset: 100,000 random squares (seeded `numpy.random.default_rng(42)`)
written to a Shapefile in the test's temp directory ([strategy.md](strategy.md#performance-tests)).
